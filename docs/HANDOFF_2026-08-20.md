## The RESTORE pair work — larger than the docs imply, and un-adjudicated

This is the single most understated thing in `docs/`. It reads as though only a
two-comparison diagnostic roster exists. That roster is the residue; this is the result.

`data/restore_gated_redsea/apply_manifest.csv` (2026-07-27, `restore-pair-validation-v10`):
**24 target→reference pairs × 20 donors = 480 rows, 480 `ACCEPTED`, 479 `VALID`.**
Downstream, `data/phenotype/broad/` holds **25,151,028 cells** fully typed with zero
`unavailable`; the run's `calibrate` / `type` / `states` stages completed 20/20 on 2026-08-05.
Only `qupath_export` never ran.

Cohort composition from those calls: Epithelial 49.4%, Immune 21.3%, Other 13.7%,
Endothelial 13.2%, Mesenchymal 2.0%, Neural 0.45%.

23 of the 24 pairs separate cleanly — `double_high_fraction` ≤ 0.008, median target folds
3.2–410. **CD11b/EpCAM does not, and passed anyway:** double-high 0.045–0.411, and donor 6591
`target_fold = 1.088`, worse than the 1.67 that triggered review elsewhere, yet `VALID` on all
20 donors. That matches the later removal of CD11b from broad Immune for failing mutual
exclusivity.

Four findings recorded after the manifest was written land on every one of its rows:

| Finding | Coverage in the manifest |
|---|---|
| `p99` agrees with the independent NNMF+floor anchor on 18/72 pairs; median calls 2.58× | `divisor_statistic = p99`, 480/480 |
| The four structural references were image-review-flagged and dropped from the roster | E_cadherin 280, CD31 100, Pan_Cytokeratin 60, EpCAM 40 |
| The Otsu input floor is 88.66× truth at 0.3% positives (the CD3e/MPO/CD8 regime) | `linear_otsu` 260 + `max_linear_otsu_triangle` 220 |
| The same roster re-run under the corrected method on 3 donors: 52/69 valid | v10 scored it 479/480 |

**Status: unverified, not disproved.** No document records the 480 rows being re-scored, and
`1e43587` — the sign-off commit itself — says the acceptance rested on *"screen diagnostics
ALONE; the per-image biological review is outstanding for all of them."*

### Two traps

- The 6566 INS row's `state_reason` reads *"image review confirms absence"*. `1e43587` records
  it as **provisional, from screen diagnostics rather than image review**, and says it *"must
  be confirmed from the image before any INS-dependent result is reported."*
  `data/restore_pair_validation/expression_reviews.csv` holds only one row, 6539/CD20 — not
  this one.
- 253 of 480 rows have `stability_informative = False` (an arm is saturated, so the seed sweep
  is arithmetically a no-op). Their high `probe_control_jaccard` is **not** validation: the
  08-12 handoff names a *"stable-but-wrong all-cell partition"* with reproducibility and
  Jaccard exactly 1.0.

### How this gets adjudicated

The accuracy instrument is the QuPath label-review loop, and it is intact for all 20 donors:

```text
data/phenotype/qupath_class/pheno_class_<donor>.csv   (object_id, compartment, cell_type, image)
  -> core/phenocycler/scripts/groovy/import_cell_assignments.groovy
  -> scripts/groovy/view_phenotypes.groovy            (toggle classes on the image, QuPath 0.7)
```

The `gold_standard_v1` annotation bundle was removed on 2026-08-20 (maintainer decision — it
was never annotated, 0 of 2,500 rows on both sheets). Removing it retires a second, unused
instrument; the QuPath loop above is unaffected. `production_status =
development_no_verified_pairs` stands until the outstanding per-image review is done through
that loop, and the v10 result stays archived historical evidence in the meantime.

`config.ini:20` already reads `divisor_statistic = empirical_alpha` and `empirical_tail.py`
exists, so the corrected divisor is in place. It has never been run over the cohort.
