## Maintainer decisions, 2026-10-19 and 2026-10-20

1. **6347 / 6533:** the workstation sends its segmentation and the lane re-prepares those donors on
   it. Delivered (A) and done.
2. **Typing:** the workstation runs the current producers and delivers cell-level calls keyed by
   `object_id`. This lane only transfers and analyses. HiPerGator has neither the pancreas chain's
   inputs (`subpanel_log.json`, the structure objects, crossed fractions, fundamentals) nor its
   2026-10-08 `subpanel.py`.
3. **One class per cell, reached in two steps:** "There should only be one class! ... the two
   designations are just steps to the same result." The pancreas class is the delivered
   `refined_class`. `immune_class` and `immune_subtype` are carried inside Immune only.
4. **pLN is a tissue, and its cells are typed:** "pLN is not a class it is a tissue that needs to
   have cell typing done based on the lymph node cell types in the phenotyping spreadsheets for
   lymph node."
   - Asked where those spreadsheets are, the maintainer named the producer.
   - `build_pln_immune_pheno.py` "types immune cells using the lineage marker sets
     (core/phenocycler/scripts/typing/lineages.py:23) and shared identity panels"
     (`core/panels/data/identity_core`).
   - The node table it produced on the workstation is transferred (below).
5. **Every cell is typed:** "typing needs to happen for all cells so for cells that exist in both
   pancreas and lymph node, use the pancreas typing methods." Read here as: a cell type found in
   both tissues is typed by the pancreas methods. The delivered node table names immune lineages
   only, so it is not the finished node typing (item D).
6. "Don't run hypotheses until the data are properly processed since the technical issues mask
   results." Everything below is descriptive.
7. **No peri-islet expansion** (2026-10-20): "The approved pipeline dropped the 20um expansion
   since all cells have distance to nearest islet features."
   - On the workstation (`analysis/cohesive-finish`), `build_cells.py` writes `cell_region` as
     `core` or `tissue` and keeps `signed_dist_islet_um` as a continuous measurement. It
     reconstructs no ring and no replacement distance band. The atlas reads true-Islet outlines
     with no expansion.
   - The delivered pancreas calls carry exactly that: `cell_region` ∈ {core, tissue}, and a
     distance on every cell.
   - That distance is to the nearest of the three whole-cell object classes. Measured on each
     donor's PhenoCycler cells against `islets/<tag>.geojson`, the lane's own signed distance
     agrees with it on all four donors: median |difference| 0.67–0.76 µm, p99 2.9–3.4 µm, and
     cells inside within 5 of `core`. Measured to Islet objects alone (0112), it does not agree
     (median 39 µm).
   - `islets_four.py` now follows the approved pipeline. Its regions are core and tissue. Every
     Xenium cell keeps `signed_dist_islet_um` and its nearest object. Coverage reads the outline
     alone. Rerun 2026-10-20.

## Stages added or changed

| script | stage root | what it does |
|---|---|---|
| `import_alignment.py` | `protein/donor_id=*/alignment` | checks each delivered file against its SHA256SUMS; refuses a donor whose delivered UUIDs are not prepared UUIDs; writes `<roi>/aligned.parquet`, pancreas-frame markers as `<marker>`, pLN-frame as `pln__<marker>`; `analysis_eligible` = lane QC ∧ nucleus ∧ the delivery's own QC |
| `recheck_nuclei.py` | `<section>/registration_recheck` | the validated transform, unchanged and unrefitted, scored against the current preparation's nuclei, held to the gate's own `threshold_pass_um` |
| `join_four.py` | `<section>/joined` | protein from **both tissues of the image** (a Xenium region is not a tissue); `feat__<m>` cohort units and `feat__pln__<m>` pLN units, never one column for both; `protein_tissue` (Tissue → pancreas, pLN → pLN) and `protein_frame` per Xenium cell |
| `associate_four.py` | `<section>/association` | independent protein–RNA association, per tissue and frame |
| `calls_four.py` | `<section>/calls` | one class from each delivered table (`protein_calls.tables`), over the join's own edges with `lift_calls.transfer_calls` (largest shared area; `call_share`, `call_purity`); refuses an object in two tables and a protein cell whose join tissue is not its table's; a table's `not_a_class` labels are carried, never awarded |
| `context_four.py` | `<section>/context` | `context.evaluate`: two spatial folds, each cell's class prior from the other fold |
| `islets_four.py` | `<section>/islets` | Islet / EndocrineCluster / EndocrineSingle objects (never a Hormone Fragment); every Xenium cell's signed distance to its nearest object in the PhenoCycler frame (`signed_dist_islet_um`), core or tissue from it with no expansion (decision 7); composition of pancreas-tissue Xenium cells only; each object beside its own PhenoCycler cells; outline coverage; RNA identity-group detection by region and class |
| `nodes_four.py` | `<section>/node_summaries` | **new.** Per node (pLN annotation), in whichever section imaged it: transferred class and T/NK subset beside the same node's overlapped PhenoCycler cells, cells without a class counted by the producer's reason, depth inside the node outline, coverage, RNA identity-group detection by class |
| `completion_four.py` | `completion/` | the matrix, from receipts only; a node summary applies to a pancreas section whose calls receipt records Xenium cells won by node cells (6347, 6580) |
| `figures_four.py` | `figures/` | **new.** Seven summary figures across sections, from current receipts only; a section whose stage is unavailable is drawn with its reason (below) |

The manifest's `protein_calls` now has a `root`, the one-class `ruling`, and `tables`. Each table
has its `tissue`, `class_column`, `within`, `carry` and `not_a_class`:

  the cluster, not the cell's own, so it is not carried.

- The corrected deficit is that threshold, not evidence of RNA loss.

## Waiting on the workstation

**D. Every node cell typed, per decision 5.** The delivered node table names immune lineages only.
It leaves the cells its clusters read structural (27–37 % of each node's Xenium cells), the cells no
lineage marker named, and `Uncalled` cells without a class.

What is asked:

- Retype every node cell of the four images, both blocks, 1,121,187 objects, so each carries one
  class.
- A cell type the node shares with the pancreas is typed by the pancreas typing methods: the
  subpanel chain → refine → immune second pass, with reference levels per donor and nothing pooled.
  The shared types are the immune lineages and their subtypes, and the structures Blood vessel,
  Lymphatic and Nerve.
- A cell type only the node has is typed by the lymph node cell types.

The run has to settle four things the pancreas chain takes from its tissue:

- What stands in for the structure objects inside a node.
- Which population gives a node cell's reference level. The pancreas and the node share a slide
  and an acquisition. The cross-slide transfer that `build_pln_immune_pheno` withdrew was between
  different slides.
- The different-block node cells' units. They are aligned in the pLN frame, not the cohort frame.
- What a node cell is when no shared type fits. Exocrine, the pancreas's last step, has no meaning
  in a node.

How to deliver it:

- Write `calls/nodes` again with the same keys: `donor_id`, `object_id`, `pln_annotation_id`,
  `block_relationship`.
- Include the class column holding the result, its targeted levels, `producer` per row, and a
  SHA256SUMS.
- Set `protein_calls.tables.nodes` (`class_column`, `within`, `carry`, `not_a_class`) to match.

Then `calls_four` → `context_four`, `islets_four`, `nodes_four` → `completion_four` rerun
everything in minutes, because the calls fingerprint includes the delivered checksums.

**Within-donor normalization (not ruled).** The delivery README records that UniFORM's per-marker
factors multiply CD8 3.7–19 times as much as CD4 on these four donors. That exposes the pancreas's
`immune_subtype` T-CD8 / T-CD4-helper calls (manifest `exposed`). If a within-donor step is ruled,
the pancreas calls come again.

## Running

All of it is minutes. Run sections side by side on an interactive node or across both investment
QOS (maigan 80 CPUs / 625 GB, clive 40 CPUs / 312 GB).

```bash
cd core/phenocycler/scripts/sameslide
export PYTHONPATH=$REPO/data/development/sameslide_four/python_deps:$REPO/core/phenocycler
M=$REPO/core/phenocycler/config/sameslide_four.json
python calls_four.py --manifest $M --section <section>
python context_four.py --manifest $M --section <section>     # every section
python islets_four.py --manifest $M --section <panc section>
python nodes_four.py --manifest $M --section <section that imaged a node>
python completion_four.py --manifest $M
python figures_four.py --manifest $M                         # after completion; about 20 s
```

Measured per section:

| stage | time | memory |
|---|---|---|
| calls | 20–50 s | ≤ 5 GB |
| context | 20–125 s, one core | ≤ 27 GB |
| islets | about 2.5 min | ≤ 12 GB |
| node summaries | 13–35 s | ≤ 8.5 GB |

`scheduler.submit` will not resubmit a completed job with an identical specification; rerun such a
stage directly.
