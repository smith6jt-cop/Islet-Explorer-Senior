Reading your fork's actual implementation (`python_code/RESTORE/RESTORE.py`) changes one thing from the table I gave above, so here's the operationalized version keyed to how your code consumes pairs — not the generic method.

**How this implementation actually consumes a pair.** The `Normalization` class takes `marker_pairs` as a list of two-element lists, and each entry is *directional*: `marker_pair[0]` is the target that gets thresholded, `marker_pair[1]` is the mutually-exclusive counterpart used only to define the negative population. Concretely, in `get_marker_pair_thresh` it fits three 2-cluster models (KMeans, GMM, SSC) on the co-expression region, identifies the negative cluster as the one with maximum spread on the *counterpart* axis, then sets `thresh = mu + 3*sigma` of the *target* within that negative cluster. The result is stored as `threshs[batch][scene][target][model]` — keyed on the target name only. This confirms the mutual-exclusivity-as-background principle the package identifies mutually exclusive marker pairs as negative controls and normalizes reference intensity by the inferred autofluorescence level of the negative, but it imposes two hard constraints:

1. **One counterpart per target, per run.** Because the storage key is the target name, a second entry with the same `marker_pair[0]` silently overwrites the first. So the two-negatives-per-target design from my table above can't be loaded as-is — each target gets its single best counterpart below. To threshold *both* members of a pair, include both directions (e.g. `["INS","GCG"]` and `["GCG","INS"]`); to compare two candidate counterparts for one target, run separate passes.
2. **`scene` and `batch` are attribute-accessed** (`self.data.scene`, `scene_data.batch`), so your DataFrame must have columns named exactly `scene` and `batch` (lowercase), plus one intensity column per marker named exactly as referenced in `marker_pairs`. No cell-id column is required by the threshold code.

**Not thresholdable via any pair — leave out** (6): DAPI and Beta-actin (segmentation/reference; nuclear stain and pan-cellular housekeeping), HLA-A (MHC-I on all nucleated cells — and in your T1D context it's *hyper*-expressed in islets, so there is no stable negative), Collagen IV (basement-membrane ECM, not a per-cell signal — use as a mask), and Ki67 / PCNA (proliferation is lineage-agnostic, so no mutually-exclusive counterpart exists; binarize these by a standalone bimodal fit instead).

CD107a, CD44, CD99, M2Gal3/Galectin-3, Caveolin, Bcl-2, SOX2 each span compartments; if you need them, pair each against a lineage it genuinely never occupies (CD20 or E-cadherin for the immune/mesenchymal-agnostic ones, CD3e for the ductal/myeloid-shared ones like M2Gal3 and Caveolin), but treat the + call as a state annotation, not a class.

**scene/batch mapping for your single-sample PhenoCycler context.** The method re-estimates background per `scene` per `batch`, which is exactly what absorbs per-image autofluorescence — the reason to prefer it over a global cutoff given your Fusion run-to-run variability. Map `scene` → ROI/region (so each region gets its own background) and `batch` → section/run/replicate. If you have one ROI and one run, set both to constants; thresholds are then estimated on the whole sample — still valid, you just lose per-region adaptivity.

**Three runtime issues that will bite on a current stack, in order of likelihood:**

- *Intensity-scale mismatch (most likely failure).* `get_marker_pair_thresh` pre-selects the co-expression region with hardcoded absolutes — `tmp[:,0] > 50` / `tmp[:,1] > 50` plus `ratio_x=0.75`, `ratio_y=0.5` — calibrated to the OHSU cycIF range. On 16-bit Fusion raw means (0–65535) `>50` is nearly always true and washes out the separatrix; on arcsinh/log/0–1-normalized values `>50` selects nothing and clustering fails on an empty array. Run `data[markers].describe()` first and either rescale to that range or edit those constants.
- *PhantomJS.* `save_figs=True` routes into `save_thresh_figs`, which calls `webdriver.PhantomJS()` — removed in Selenium 4, so it raises on modern Ubuntu. Run with `save_figs=False` for the first pass (you still get `threshs.pkl`); to recover the QC overlays, swap the export to a headless-chromedriver `export_png` or switch the holoviews backend to matplotlib (the `hv.save` HTML step itself is fine).
- *Fixed `sigma_weight=3`.* μ+3σ is global across every marker with no per-marker knob unless you parameterize it (it's flagged `#TODO`). Sparse markers (FOXP3, Granzyme B, TOX) are where the three models diverge most, so decide up front whether you take one model or the median across KMeans/GMM/SSC from the nested `threshs` output.
